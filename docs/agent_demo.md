# 流浪猫喂养平台 — 3分钟 Demo 脚本

## 核心设计原则

**所有交互只在一个对话框里完成：没有跳转页面，没有冗余结果卡片。**

- **不是「表单式 Chatbox」**：用户主导，想到什么问什么；Agent 被动回答并调用工具。
- **仅在信息缺失时追问**（例如没有位置时才问「你在哪里？」）。
- **多轮有上下文**：同一会话记住刚上传的照片、位置、角色意图，不必重复交代。
- **分析结论不进独立结果页**：绝育/健康判断与建议以**对话气泡**为主；地图热力图作为侧边或嵌入视图同步更新。

---

## 业务流程概览

```
用户在对话框发照片或文字
              ↓
        Agent 分析 + 工具调用
              ↓
    健康未绝育 → 联系就近救助中心安排 TNR
    受伤       → 联系就近救助中心救治
    健康已绝育 → 记录数据库，更新热力图
              ↓
    用户也可直接提问 → Agent 调用真实数据回答
```

---

## Agent 四类能力

### 1. 工具调用（真实数据）

与 **Spring Boot REST API / 数据库** 对齐，概念工具名示例：

| 概念工具 | 用途 |
|----------|------|
| `get_cat_count_nearby` | 查附近猫咪数量 |
| `get_feeders_nearby` | 查最近喂食器位置 |
| `find_rescue_center` | 查就近救助中心 |
| `checkin_feeding` | 志愿者投食打卡 |
| `report_cat` | 上报新猫记录 |

实现层可映射到现有接口（如猫咪 lookup、喂食器列表、目录 nearest、打卡 POST 等）；**演示时以真实返回为准**，避免模型编造数字。

### 2. 联网搜索（与数据库无关时自动触发）

- 使用 **Tavily / DuckDuckGo** 等实时搜索（按工程实际选型）。
- **适用**：流浪猫知识问答、绝育科普、疾病处理、喂养建议等开放域问题。
- **路由**：数据库相关 → 调工具；纯知识性问题 → 联网搜索（或由 Agent 判定混合回答）。

### 3. 知识库 RAG

- 流浪猫喂养指南  
- TNR 绝育科普  
- 常见疾病处理方法  

### 4. 多模态照片分析

- 判断是否已绝育（耳尖 / 剪耳）  
- 判断健康或受伤状态  
- 估算年龄（粗粒度即可）

## 对话里发照片后应呈现什么（演示预期）

**用户侧（气泡）：** 文字（可选）+ 猫咪照片缩略图。

**Agent 侧（同一流式对话里，可 1～2 条气泡）：**

1. 分析结论（绝育、健康/受伤、大致年龄等）。  
2. 已执行侧（若有）：例如「已将位置记入社区地图」。  
3. 行动建议 + 可选快捷话术（如是否联系就近机构安排 TNR）。

**禁止：** 再堆一套与对话重复的「结果卡片」作为主流程；**主入口只有对话框**，地图仅作视觉增强。

## 多轮对话示例（产品预期）

```
👤 [发送照片]
🤖 成年公猫，未绝育，健康。附近有 Humane Society，是否联系 TNR？
👤 先不用。附近还有多少只未绝育的猫？
🤖 （调用工具）你附近 1km 内共 24 只未绝育，本周新增 3 个目击点。
👤 最近的喂食器还有粮吗？
🤖 （调用工具）Weller Lane 喂食器距你 320m，上次补食今天 9:30，状态充足。
👤 好，帮我联系救助中心。
🤖 已提交申请，救助中心将在 24h 内回复。
```

## 第一幕：市民发现猫（0:00 - 0:40）

**演示操作：** 在对话框直接发送照片。

**Agent 在对话里回复：**

> 📷 分析完成：成年公猫，未检测到耳尖剪缺，判断未绝育，健康状态良好。已将位置记录到社区地图。  
> 附近 500 米有 Humane Society of Silicon Valley，是否联系安排 TNR 绝育手术？

**视觉效果：** 对话框旁地图热力图出现新的橙色聚集点。

---

## 第二幕：数据查询（0:40 - 1:20）

**用户输入：** 「附近现在有多少只猫？」

**Agent 调用数据库后回复：**

> 📍 你附近 1km 范围内共记录到 **32 只**流浪猫，其中 8 只已绝育，24 只未绝育。本周新增 3 个目击点。

**用户输入：** 「最近的喂食器在哪里？」

**Agent 回复：**

> 🍽️ 最近的喂食器在 Weller Lane 公园入口，距你 **320 米**，上次补食时间：今天上午 9:30，当前状态：充足。

---

## 第三幕：志愿者打卡（1:20 - 1:50）

**切换角色：** 志愿者视角。

**输入：** 「我今天去喂猫，去哪里？」

**Agent 回复：**

> 🗺️ 为你规划今日路线：3 个喂食点，预计 45 分钟。从最近的 South Point 开始 → Weller Lane → Berryessa Park。要开始导航吗？

**输入：** 「South Point 喂完了」

**Agent 回复：**

> ✅ 打卡成功！South Point 今日投食记录已更新，热力图已刷新。还有 2 个点待完成。

**视觉效果：** 地图上该点由红变绿。

---

## 第四幕：救助中心视角（1:50 - 2:30）

**切换角色：** 救助中心工作人员。

**输入：** 「今天有什么新上报？」

**Agent 回复：**

> 📋 今日新增：绝育申请 2 个，受伤上报 1 个。建议优先处理北区受伤猫；距你最近的志愿者张三在附近，是否通知他协助？

**视觉效果：** 地图显示派单路线（若产品已支持）。

---

## 第五幕：结尾数据（2:30 - 3:00）

**用户输入：** 「本周成果怎么样？」

**Agent 回复数据（示例表，演示前请与真实或 Mock 对齐）：**

| 指标 | 本周数据 |
|------|----------|
| 志愿者投食打卡 | 47 次 |
| 绝育手术完成 | 12 只 |
| 受伤猫咪救治 | 3 只 |
| 活跃喂食点 | 8 个 |
| 覆盖流浪猫 | 32 只 |

**结尾台词：**

> 每一个观察者的行动，都让一只猫从叠加态坍缩到安全。

## 关键准备事项

- **Mock 数据提前准备好**，不要现场干等 API。  
- **热力图颜色变化**是最抓眼球的视觉效果，重点演示。  
- **两个浏览器窗口**分别演示市民 / 志愿者 / 救助中心角色。  
- **Agent 可预设固定回复或严格工具 JSON**，避免 LLM 现场漂移。  
- **工具必须打真实接口**：「问数量 / 问喂食器 / 本周汇总」若靠模型胡编会立刻露馅；宁可少工具也要稳定。

## 技术架构

```
对话框（唯一入口）
        ↓
Python Agent（LangGraph）
   ├── 工具调用 → Spring Boot REST API → 数据库
   ├── 联网搜索 → Tavily / DuckDuckGo（开放域知识）
   ├── 知识库   → RAG（喂养 / TNR / 常见病文档）
   └── 多模态   → 照片分析（绝育 / 健康 / 年龄）
```

## 混合路由：规则快速通道 + 大模型工具调用

`classify` 节点现在是混合路由（`cat-agent/llm_router.py` + `ai_service.classify_node`）：

1. **规则快速通道**：IoT 快照、`[nearby_shelters]` 标记，以及会写数据或答案固定的意图（喂养打卡 `checkin_feeding`、上报新猫 `report_cat`、平台统计）直接走原来的正则路由，不调用模型。**会写数据的工具从不交给模型决定。**
2. **大模型选工具**：其余问题由 `gpt-4o-mini` 通过 tool calling 选择工具（每轮最多 3 个）：`get_cat_count_nearby`、`get_feeders_nearby`、`find_rescue_center(kind)`、`query_assessments_nearby`、`get_assessment_detail(focus)`、`get_cat_sightings_timeline(cat_id)`、`get_same_cat_cluster_timeline`、`search_knowledge_base(query)`、`web_search_facilities(query)`。
   - 选了 **1 个工具**：沿用原来的节点（回复格式与之前一致）。
   - 选了 **多个工具**（复合问题）：`multi_tool` 节点并行执行，再综合成一段回答。
3. **兜底**：模型报错、超时（`AGENT_LLM_ROUTING_TIMEOUT`，默认 8 秒）、没选工具或参数不合法（例如没有打开评估却要查评估详情）时，自动退回正则路由。

开关：`AGENT_LLM_ROUTING=false` 完全恢复为纯规则路由。

### 演示时怎么展示「模型自己选了哪个工具」

SSE 的 `route` 事件现在带上 `routing_mode`（`rule` / `llm` / `fallback`）和 `tools`，cat-agent 日志也会记录 `route=… mode=llm tools=[…] router_ms=…`。推荐的对比问题：

| 问题 | 预期 |
|---|---|
| 我刚喂完了，帮我打卡 | `mode=rule`（写数据，不经模型） |
| 我捡到一只受伤的小猫，这边有没有能收留它的组织？ | 规则识别不了的换种说法 → `llm`，`find_rescue_center` |
| 附近有多少只流浪猫？顺便问一下哪里能做 TNR？ | 复合问题 → `multi`，两个工具一起回答 |

测试：`cd cat-agent && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest`（用假模型，不调用 OpenAI）。
